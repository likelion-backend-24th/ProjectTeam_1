# 사례 23 - 장시간 로그인 후 재접속 시 자동 로그아웃되는 문제

기술 스택: Next.js, React, Tailwind
생성일: 2026년 8월 27일 오후 3:18
참고인: 김종범, gh, 승욱 곽, songsihun, KimDasom

## 📌 문제 발생

1. 로그인한 상태로 장시간(액세스 토큰 유효기간인 1시간 이상) 두었다가 다시 앱에 들어가면, 리프레시 토큰이 아직 유효한데도 무조건 "로그인이 필요합니다" 화면이 뜸

2. 재로그인 없이 세션이 자동으로 이어져야 하는 게 정상 동작인데, 매번 다시 로그인해야 하는 상황

---

## 🔍 원인 분석

- 토큰 만료 정책: 액세스 토큰 1시간(3600000ms), 리프레시 토큰 14일(1209600000ms) — 리프레시 토큰 자체는 충분히 오래 살아있음
- authStore.js의 init() 함수가 앱 시작 시 액세스 토큰으로 getMyProfile()을 호출하는데, 토큰이 만료돼서 401이 나면 catch 블록에서 리프레시 토큰으로 재발급을 시도해보지도 않고 바로 accessToken/refreshToken을 둘 다 지우고 로그아웃 상태로 전환해버림
- 백엔드의 재발급 API(reissueAccessToken)와 프론트의 reissueApi 함수 자체는 이미 존재했지만, 실제로는 호스트 승격 시 JWT 권한 클레임을 즉시 갱신하는 용도로만 쓰이고 있었고, "세션 연장"이라는 원래 목적으로는 어디에서도 호출되지 않고 있었음

---

## 🛠 해결 방법

1. 액세스 토큰으로 프로필 조회 시도
2. 실패하면 → 리프레시 토큰이 있는지 확인 → 있으면 재발급 API 호출 → 새 액세스 토큰으로 프로필 조회 재시도
3. 그마저 실패하거나 리프레시 토큰이 없으면 → 그때 비로소 토큰 삭제 및 로그아웃 처리

---

## 🧠 배운점

- 재발급 API가 코드에 "존재"하는 것과 "실제로 쓰이는 곳이 있는 것"은 다름 — 다른 용도로 재활용되고 있어서 있는 것처럼 착각하기 쉬움
- 인증 실패(401) 시 무조건 로그아웃시키기 전에, 항상 "재발급으로 복구 가능한 상황인가"부터 확인하는 게 기본 패턴이어야 함
