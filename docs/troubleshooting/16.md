# 사례16 - 원데이클래스 설명 수정

## 📌 문제 발생

1. 원데이클래스 설명 수정 API에 빈 값 보내면 400이 아니라 500 에러가 떴다. 프론트 입장에선 뭐가 잘못됐는지 알 수 없는 서버 오류로만 보이는 상황.

---

## 🔍 원인 분석

- DTO에 NotBlank로 검증은 걸어놨는데 검증 실패하면 스프링이 MethodArgumentNotValidException을 던진다. 근데 GlobalExceptionHandler를 보니까 CustomException이랑 그냥 Exception 딱 두 개만 잡고 있었고 이 예외는 둘 다 안 걸려서 결국 캐치올(Exception.class)로 떨어져 무조건 500으로 나가고 있었다. 확인해보니 이거 설명수정 API만의 문제가 아니라 Valid를 쓰는 회원가입, 클래스등록, Host승격 등 앱 전체 API가 다 똑같이 검증 실패 시 500이 나는 상황이었다.

---

## 🛠 해결 방법

- GlobalExceptionHandler에 MethodArgumentNotValidException 핸들러를 추가했다. 검증 실패한 첫 번째 필드의 에러 메시지를 꺼내서 400으로 내려주도록 고쳤다. 로컬에서 버그 재현하고 수정 후 같은 요청으로 재검증까지 마쳤다.

---

## 🧠 배운점

- 컨트롤러/서비스 로직 자체가 맞아도 예외처리가 빠지면 프론트한테는 엉뚱한 에러로 보인다는 걸 알았다. 새 API 만들 때 정상 케이스만 테스트하지 말고 잘못된 입력값 넣었을 때 에러 응답이 제대로 나오는지도 같이 확인해야겠다.
